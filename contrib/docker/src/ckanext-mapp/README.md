# ckanext-mapp

The MaPP site's customisations, in one extension.

They used to live on a `mapp_master` branch in three different checkouts —
`ckanext-cioos_theme`, `ckanext-spatial` and `cioos-siooc-schema` — which meant
MaPP could only be deployed by checking out a different branch of each
submodule, and every upstream merge had to be done three times over. Everything
here is expressed through published CKAN extension points instead, so those
branches can be retired and the checkouts can track the shared CIOOS/Hakai line.

This is the same move `ckanext-hakai` made for the Hakai-only patches; see its
README for the extension-point rules (template precedence, preset ordering).

## Enabling it

`ckanext-mapp` is installed into every image but does nothing unless
`ckan.plugins` names it. The live plugin list comes from the `CKAN__PLUGINS`
environment variable via `ckanext-envvars`, not from the ini file.

```ini
ckan.plugins = ...
               cioos_theme
               mapp
               cioos_harvest
               mapp_harvest
```

**Ordering matters.**

- `mapp` must come **after** `cioos_theme`. CKAN resolves template directories
  and `ITemplateHelpers` in plugin order with later plugins winning, and the
  facet work in `MappPlugin` rewrites the facet dict cioos_theme has already
  built and ordered.
- `mapp_harvest` must come **after** `cioos_harvest`, because it writes the
  MaPP fields straight into the package dict cioos_harvest assembles.

### Config

```ini
scheming.dataset_schemas = ckanext.mapp:schemas/mapp_schema.json
licenses_group_url       = file:///srv/app/src/ckanext-mapp/ckanext/mapp/schemas/ckan_license.json

# the MaPP homepage layout
ckan.homepage_style = 5

# the MaPP colour overrides
ckan.cioos.ra_css_path = /mapp.css

# the MaPP study area / sub-region outlines drawn on every map
ckanext.spatial.common_map.geoJsonLayerURLs = ["https://<site>/layers/MaPP_Sub_Region_fill_Simplify_WGS84.json"]
```

`scheming.presets`, `scheming.organization_schemas` and
`scheming.group_schemas` are unchanged from the Hakai deployment — MaPP does not
diverge there.

Note the layer URLs move: on `mapp_master` the GeoJSON sat in cioos_theme's
`public/base/layers/`, so the URLs ended in `/base/layers/...`. They are served
from this extension's own `public/layers/` now.

## What it holds

### `schemas/mapp_schema.json`

A full copy of the dataset schema, because scheming needs a complete file —
there is no overlay mechanism. It was generated from `cioos-siooc-schema`'s
`hakai_master` schema (the CKAN 2.12-ported one) plus the MaPP delta:

- adds `mapp-theme`, `mapp-sub-theme` (single `select`), `mapp-sub-region`
  (`multiple_select`) and `mapp-project` (`tag_string_autocomplete`), after
  `keywords_translation_method`
- drops `lineage` and `topic-category`, which MaPP does not collect
- `keywords` loses the `tag_length_validator`
- `spatial` gets `display_snippet: null`, hiding the raw geometry in the
  "Additional Info" table

Three things on `mapp_master` were deliberately **not** carried over, because
they are stale rather than MaPP decisions:

- `version`'s validator list, which still names the `unicode` validator that
  CKAN 2.12 removed. The Hakai schema's `unicode_safe` is kept.
- the `harvest_document_content` field, dropped on `hakai_master` when it
  stopped being indexed.
- `alternate_languages`, absent from the older base `mapp_master` forked from.

When the shared schema changes, this file has to be regenerated by hand. The
delta above is the whole of it.

### `schemas/ckan_license.json`

The Hakai licence list plus the 23 DataBC licences MaPP harvests against, and
MaPP's wording for `OGL-CAN-2.0` and `OGL-BC-2.0`.

### `plugin.py` — `mapp`

- **`IFacets`.** Inserts Theme / Sub Theme / Region / Project after
  cioos_theme's `ecv` facet, and drops `projects`, which `mapp-project`
  replaces. The dict is unpacked and refilled rather than appended to, because
  cioos_theme has already ordered it and a plain assignment would land the MaPP
  facets at the bottom.
- **`IPackageController.before_dataset_index`.** Parses the stored JSON for
  `mapp-sub-region` and `mapp-project` so Solr indexes them as lists.
  cioos_theme does the same for its own repeating fields; the MaPP ones are not
  in its list.
- **`IPackageController.after_dataset_show` / `after_dataset_search`.** Tidies
  the contacts cioos_theme has already grouped: reduces each
  `contact-info_online-resource` JSON blob to its `url`, and collapses the
  duplicate addresses a contact accumulates when it appears under several roles
  into one comma-joined string. On `mapp_master` this was two `try`/`except
  Exception: pass` blocks inside cioos_theme's `group_by_ind_or_org` — its own
  commit message called it "a terible hack". Same output, from outside.
- **`ITemplateHelpers`.** Overrides `cioos_append_to_homepages` to add MaPP's
  layout to the dropdown in `/ckan-admin/config`, keeping the CIOOS entry
  cioos_theme registers.

### `harvest.py` — `mapp_harvest`

MaPP tags its ISO 19115-3 records with four controlled vocabularies, each an
`MD_Keywords` block whose thesaurus title names the vocabulary (`MaPP Theme`,
`MaPP Sub-Theme`, `MaPP Sub-Region`, `MaPP Project`).

On `mapp_master` these were four extra `ISOElement`s patched into
ckanext-spatial's `ISODocument`. **That patch has no extension point**:
`ckanext/spatial/harvesters/base.py` hardcodes
`ISODocument(harvest_object.content)`, so the parser cannot be swapped.
`ISpatialHarvester.get_package_dict` is handed the parsed `xml_tree`, though,
so the same xpaths run from there instead and write the four fields into the
package dict directly.

### `templates/`

| Template | Why |
|---|---|
| `header.html` | the CIOOS "mega menu" header, which `hakai_master` reverted cioos_theme's copy away from. MaPP's version has an empty top bar: no social list, no top-bar language picker, no CIOOS banner logo. |
| `footer.html` + `footer/mapp_footer.html` | the MaPP footer wrapper and links. |
| `menu/mapp_menu_list.html` | the MaPP main menu. Moved out of cioos_theme, where it was the only MaPP-specific file left. |
| `home/layout5.html` | the MaPP homepage: search hero, "about" beside the site statistics, then the spatial search map. It was `layout3.html` on `mapp_master`; it is numbered 5 here so it sits alongside cioos_theme's layouts rather than masking layout3 for the other sites. |
| `home/snippets/promoted.html` | "Metadata Catalogue", not "Data Catalogue", with the heading inside the box. |
| `package/read.html` | `ckan_extends` with an empty `package_citation` block — MaPP shows no citation. |
| `package/read_base.html` | `ckan_extends` with the Lineage tab removed, since `lineage` is not in the MaPP schema. |

`header.html` and `footer.html` are full copies rather than `ckan_extends`
overrides because the markup they replace in cioos_theme is not inside a Jinja
block. The menu and footer snippets are imported by path instead of through
`ckan.header_file_name` / `ckan.footer_file_name`: there is only one site here,
so the indirection bought nothing.

### `public/`

`mapp.css` (the MaPP palette and header/footer overrides, loaded via
`ckan.cioos.ra_css_path`) and the three MaPP GeoJSON outlines.

### `i18n/`

One translated string, `Metadata Catalogue`, carried over from what
`mapp_master` added to cioos_theme's French catalogue. The rest of the MaPP
strings were never translated and are left empty rather than guessed; they fall
back to English.

## Deliberate differences from `mapp_master`

Flagged here rather than silently fixed or silently copied.

- **`mapp-sub-region` keeps its list shape.** `mapp_master`'s `infer_tag_string`
  ran `', '.join(...)` over all four vocabularies. That is right for the two
  `select` fields and for `tag_string_autocomplete`, but `mapp-sub-region` is a
  `multiple_select`, whose validator wraps a string as a one-element list — so a
  record in two sub-regions produced `["Haida Gwaii Sub-Region, North Coast
  Sub-Region"]`, which is not a valid choice and fails validation. This
  extension passes the list through.
- **The Activity Stream tab is left alone.** `mapp_master` has it on and
  `hakai_master` has it commented out, but that is branch drift, not a MaPP
  decision — the MaPP commits only ever touched the Lineage tab. MaPP inherits
  whatever cioos_theme does.
- **`hide_header` on the spatial query snippet is dropped.** `mapp_master` added
  the flag to ckanext-spatial but no MaPP template ever passed it.
- **The `thesaurus` element on `ISOKeyword` is dropped.** `mapp_master` added it
  to the parser and threaded it through `values['keywords']`, but nothing reads
  it. The MaPP vocabularies are matched on thesaurus title directly in
  `harvest.py`.
- **`mapp-project` still facets as one value.** `tag_string_autocomplete` stores
  a comma-separated string, so a record with two projects yields a single facet
  reading `"Project A, Project B"`. This is `mapp_master`'s behaviour, kept as
  is; fixing it means changing the field's preset and migrating stored values.

## Solr

The four MaPP fields are declared in `ckan/config/solr/schema.xml`, alongside
`eov`/`ecv`, and copied into `text`, `text_en` and `text_fr`. They are inert on
the other sites, but they cannot be left to the catch-all `*` dynamicField:
that one is single-valued, so a dataset in two sub-regions would fail to index.

All four are `multiValued`, matching the schema the MaPP deployment already
runs (parent branch `MaPP_master`). `mapp-theme` and `mapp-sub-theme` are
single `select` fields and only ever carry one value, but declaring them
single-valued would turn any legacy multi-valued record into an indexing
failure.

## Still on the MaPP branches, and why

The three submodule `mapp_master` branches are fully represented here. They are
left in place for history; nothing in this repository points at them any more.

The **parent repository** also has a `MaPP_master` branch, which holds two
things this extension does not:

- **`contrib/docker/docker-compose.mapp.yml`.** It differs from the shared
  `docker-compose.yml` only in the image tag
  (`hakaiinstitute/ckan:mapp_${CKAN_TAG}`), a few CPU limits and whitespace.
  Under one-image-many-plugins there is no MaPP image to tag, so it should
  collapse into the shared compose file plus a MaPP `.env`.
- **`contrib/docker/migrations/mapp_ckan_1.5.0.sql`.** A one-off 2.9-era data
  migration that rewrites `contact-info_online-resource` from a bare URL into
  the JSON blob form and strips `position-name` — the same shape the contact
  normalisation above produces at read time, for records that predate it. It
  operates on `package_extra`, **which CKAN 2.12 dropped**, so it cannot be run
  as-is against a 2.12 database.

Neither has been moved. A shell script and a SQL file are deployment artefacts,
not extension content.
